## 1. Governance Principles & Role Hierarchy Mechanics

The SmartHotel system enforces authorization across 16 operational identities via a table-driven authorization matrix (`Role`, `Permission`, `RolePermission`). At the Next.js Edge routing boundary (`middleware.ts`), authentication JWT sessions assert an integer `levelWeight` (ranging from 0 for public guests to 100 for platform architects). 

### Golden Security Rules
1. **Default Deny Doctrine:** All API endpoints, Server Actions, and Administrative viewports default to completely restricted (`403 Forbidden`) unless an explicit role or permission grant is associated with the accessing user account.
2. **Horizontal Tenant Isolation:** Even if a user possesses appropriate role weights, programmatic data filtering MUST apply in all database queries to prevent horizontal leakage across different corporate identities, travel agencies, or physical storeroom inventory locations.
3. **Immutable Financial Ceilings:** Monetary overrides (discounts, refunds, price alterations, purchase order authorizations) enforce hard ceiling thresholds per role level. Exceeding an override ceiling systematically forces the operation into a multi-party Managerial PIN approval workflow.
