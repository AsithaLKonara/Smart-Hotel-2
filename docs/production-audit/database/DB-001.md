# DB-001 - PostgreSQL / MongoDB Configuration Mismatch

## Status

**Resolved** (Standardized strictly on PostgreSQL)

## Severity

P0 - Critical

---

## Category

DATABASE

---

## Description

The Prisma datasource is configured for PostgreSQL while the deployment documentation and env.example instruct operators to configure MongoDB. This causes the application to fail during startup or connect to an invalid database.

---

## Affected Files

- prisma/schema.prisma
env.example
docs/archive/ALL_REQUIRED_ENV_VARIABLES.md

---

## Root Cause

Legacy MongoDB documentation was never updated after migration to PostgreSQL.

---

## Production Impact

- Production boot failure
- Migration failures
- Prisma initialization errors

---

## How to Reproduce

1. Compare datasource provider.
2. Verify DATABASE_URL.
3. Run `npx prisma validate`
4. Run `npx prisma migrate status`

---

## Fix Guide

Step 1: Update env.example
Step 2: Update documentation
Step 3: Remove MongoDB references
Step 4: Run migration validation

---

## Acceptance Criteria

- prisma validate passes
- DATABASE_URL uses PostgreSQL
- Documentation updated
- Fresh install succeeds

---

## Regression Tests

- Environment audit
- Fresh deployment
- Production startup

---

## Priority

Sprint 1

---

## Resolution

- **Standardized Configuration**: Updated all `.env.example` templates, Vercel deployment scripts, and backend setup documentation to exclusively reference standard PostgreSQL configurations.
- **Removed MongoDB Artifacts**: Identified and removed obsolete MongoDB files and logic across `lib/db-helpers.ts` and archive documentation.
- **Validation Added**: Patched `scripts/validate-env.js` and `scripts/audit/environment-check.ts` to enforce PostgreSQL dialect requirements and aggressively block startup if legacy configurations are detected.
