# DB-002 - Dual Connection Pooling (Prisma + raw pg)

## Status

**Resolved** (Unified under Prisma `SqlTransactionClient`)

## Severity

P1 - High

---

## Category

DATABASE

---

## Description

The application uses both Prisma ORM and a raw `pg` pool (`DatabaseClient.runInTransaction`). Managing two separate connection pools increases the risk of connection starvation, deadlocks, and maximum connection exhaustion.

---

## Affected Files

- lib/db/database-client.ts
prisma/schema.prisma

---

## Root Cause

Custom serialization transactions required raw SQL handling not initially supported or preferred via Prisma.

---

## Production Impact

- Connection starvation
- Deadlocks
- Exhaustion of PostgreSQL max_connections

---

## How to Reproduce

Review `DatabaseClient.runInTransaction` usage alongside standard Prisma queries.

---

## Fix Guide

Step 1: Refactor raw `pg` queries to use Prisma `$executeRaw` or interactive transactions where possible.
Step 2: Configure PgBouncer / Direct URL properly if dual pools are maintained.

---

## Acceptance Criteria

- Verify single connection pool manager is used.
- Monitor active connections during load test.

---

## Regression Tests

- Load test API endpoints that hit both databases.

---

## Priority

Sprint 2

---

## Resolution

- **Unified Connection Pool**: Removed the redundant `pg` library connection pool and routed all raw SQL requests directly through Prisma's connection pool via `prisma.$transaction()`.
- **Backward Compatibility**: Created a lightweight adapter inside `DatabaseClient.runInTransaction` that wraps Prisma's raw SQL execution while perfectly mimicking the `pg` library API signature (`{ rows, rowCount }`). This ensures complex queries execute without structural changes.
- **Strict Typing**: Transitioned from untyped `PoolClient` to a strictly typed `SqlTransactionClient` across all messaging and database repositories.
- **Deadlock Mitigation**: Preserved the exponential backoff retry loop for database serializability failures (P2034, 40001, 40P01) using native Prisma interactive transactions.
