# API-006 - Varying HTTP Status Codes for AuthZ

## Severity

P3 - Low

---

## Category

API

---

## Description

Role authorization failures inconsistently return 401 in PUT and 403 in PATCH for the same condition.

---

## Affected Files

- app/api/rooms/[id]/route.ts

---

## Root Cause

Inconsistent developer practices across route handlers.

---

## Production Impact

- Confusing frontend error handling.

---

## How to Reproduce

Access PUT and PATCH routes without admin privileges.

---

## Fix Guide

Step 1: Standardize on 403 Forbidden for insufficient permissions.

---

## Acceptance Criteria

- Both routes return 403.

---

## Regression Tests

- RBAC integration tests.

---

## Priority

Sprint 3

---

## Resolution

- **Action Taken**: Separated the single `!session || !allowedRole` check into two distinct checks for both `PUT` and `DELETE` route handlers in `app/api/rooms/[id]/route.ts`. Missing sessions now return 401 Unauthorized, while insufficient role privileges return 403 Forbidden.
- **Verification**: Ensured AuthZ behavior aligns across PATCH, PUT, and DELETE handlers for rooms.
