# API-002 - Flattened Room Models Mismatch

## Severity

P2 - Medium

---

## Category

API

---

## Description

`GET /api/rooms/[id]` flattens `roomType` data, but frontend expects standard Prisma `Room` model with nested relations.

---

## Affected Files

- app/api/rooms/[id]/route.ts
lib/booking-api.ts

---

## Root Cause

Legacy compatibility in API response format.

---

## Production Impact

- Missing room details on frontend (undefined properties).

---

## How to Reproduce

Load single room details page.

---

## Fix Guide

Step 1: Update API to return nested relations matching Prisma schema, or update frontend types.

---

## Acceptance Criteria

- Room details page renders correctly with all specs.

---

## Regression Tests

- Room details E2E tests.

---

## Priority

Sprint 2

---

## Resolution

**Status:** Resolved
**Date:** 2026-07-11
**Fix Details:**
- Removed manual mapping of `roomType` fields onto the root `Room` object in both `app/api/rooms/route.ts` and `app/api/rooms/[id]/route.ts`.
- Endpoints now return the pristine Prisma model representation (`{ ...room, roomType: { ... } }`).
- Refactored `lib/booking-api.ts` `Room` return types to officially type the nested relations using `Room & { roomType: RoomType }`.
- Updated `app/admin/rooms/page.tsx` rendering to map values from the nested `.roomType` property instead of expecting flattened root properties (e.g. `room.roomType.baseRate` instead of `room.price`).
