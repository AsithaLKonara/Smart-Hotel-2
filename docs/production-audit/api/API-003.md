# API-003 - Missing Complaints Schema Validation

## Severity

P1 - High

---

## Category

API

---

## Description

`POST /api/complaints` lacks Zod schema validation, making it vulnerable to injection and invalid data types.

---

## Affected Files

- app/api/complaints/route.ts

---

## Root Cause

Endpoint deployed quickly without robust input validation.

---

## Production Impact

- Database corruption via invalid enum states.
- Potential NoSQL/SQL injection or large payload DoS.

---

## How to Reproduce

Send POST request with invalid status string.

---

## Fix Guide

Step 1: Implement Zod schema parsing for the request body.

---

## Acceptance Criteria

- API rejects invalid payloads with 400 Bad Request.

---

## Regression Tests

- Complaints API integration tests.

---

## Priority

Sprint 1

---

## Resolution

**Status:** Resolved
**Date:** 2026-07-11
**Fix Details:**
- Implemented `zod` schema validation for both `POST` (createComplaintSchema) and `PATCH` (updateComplaintSchema) endpoints.
- Replaced manual property checks with `schema.safeParse()`.
- Validates field constraints and ENUM correctness (`Priority`, `Status`) to prevent database corruption.
- API now returns strict 400 errors containing `validation.error.flatten().fieldErrors` when bad payloads are submitted.
