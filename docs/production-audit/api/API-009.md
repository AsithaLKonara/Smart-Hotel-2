# API-009 - Complaints IDOR Vulnerability

## Severity

P0 - Critical

---

## Category

API

---

## Description

Users can pass `?userId=TARGET-ID` to read other users' complaints due to flawed query logic.

---

## Affected Files

- app/api/complaints/route.ts

---

## Root Cause

Insufficient authorization checks on query parameters.

---

## Production Impact

- Severe data privacy breach (IDOR).

---

## How to Reproduce

Log in as Guest A, pass `?userId=GuestB` to the GET endpoint.

---

## Fix Guide

Step 1: Enforce `if (!isAdmin) { where.userId = session.user.id }` regardless of query params.

---

## Acceptance Criteria

- Guest A receives 403 or only their own complaints when requesting Guest B.

---

## Regression Tests

- Security/RBAC audit tests.

---

## Priority

Sprint 1

---

## Resolution

- **Action Taken**: Explicitly checked for the `isAdmin` boolean. If the user is not an admin, it forcibly assigns `where.userId = session.user.id`, ignoring the `?userId=` query parameter.
- **Verification**: Verified that a normal guest can no longer view the complaints of another guest by overriding the query parameter.
