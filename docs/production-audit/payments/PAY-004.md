# PAY-004 - Non-Idempotent Captures and Refunds

## Severity

P1 - High

---

## Category

PAYMENTS

---

## Description

Manual captures/refunds call Stripe without `idempotencyKey`. If DB fails, retries will attempt double-capture.

---

## Affected Files

- lib/integrations/stripe-gateway.ts

---

## Root Cause

Missing standard Stripe idempotency practices.

---

## Production Impact

- Unrecoverable state desynchronization.

---

## How to Reproduce

Crash DB immediately after successful Stripe capture.

---

## Fix Guide

Step 1: Generate and pass `idempotencyKey` to Stripe SDK calls.

---

## Acceptance Criteria

- Retries use same idempotency key and succeed gracefully.

---

## Regression Tests

- Stripe capture/refund mocked tests.

---

## Priority

Sprint 2
